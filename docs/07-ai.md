# 07 · 阶段六：敌方 AI

## 目标

电脑对手能独立完成「采矿 → 按建造顺序造建筑 → 训练军队 → 集结 → 进攻」的完整循环，对玩家形成可感知的压力。

## 验收标准

- [ ] AI 的采矿车自动采矿，资金持续增长。
- [x] AI 先部署 MCV，再按主基地 → 发电厂 → 矿场 → 兵营 → 防御 → 战车工厂 → 雷达站的顺序放置建筑；电力不足时暂停耗电设施。
- [ ] AI 持续训练单位，兵力随时间增长。
- [ ] 兵力攒到阈值后 AI 发动进攻；进攻部队被消灭后撤退/重建，再攒下一波。
- [ ] AI 基地被攻击时，附近单位回防。

## 设计意图

**为什么先做有限状态机（FSM），不做通用决策树/效用系统？**

AI 的复杂度是无底洞。对第一版，AI 只需要「有节奏地发展、给玩家压力」即可，FSM 足够：状态少（发展、集结、进攻、防守）、转移条件简单（定时器 + 兵力阈值 + 受袭事件），每个状态内是几条朴素规则。先让 AI「会玩」，再谈「玩得好」。通用 AI 框架（效用评分、机器学习）在原型期是纯粹的负债。

**为什么要拆「战略层」和「战术层」？**

- **战略层**（每几秒醒一次）：我现在该造什么？钱够不够？要不要进攻？——管钱、管建造顺序、管节奏。
- **战术层**（每 tick 或每秒）：这队兵现在去哪、打谁？——管单位行动。

两层频率不同、职责不同，拆开之后每一层都简单。这也是经典 RTS AI 的通用分法，后面 AI 变聪明（侦查、骚扰、兵种克制）时，只需要丰富某一层，不用推倒重来。

**为什么 AI 也走「命令系统」而不是直接改状态？**

AI 的本质就是「会自己产生命令的玩家」。让 AI 和人类一样通过命令队列操作单位，就能复用全部输入校验、寻路、落点分配逻辑；而且 AI 命令也是命令流的一部分，回放时自动重演（[01 决策四](./01-architecture.md)），不需要为 AI 写特殊回放。

## 实现思路

### 1. AI 状态机

```ts
export type AiState = 'develop' | 'buildUp' | 'attack' | 'defend';

export interface AiBrain {
  state: AiState;
  nextThinkTick: number;     // 战略层下次思考时间
  buildOrder: string[];      // 预设建造顺序，动态裁剪
  attackThreshold: number;   // 攒多少兵进攻
  waveTarget: number | null; // 本波进攻目标实体 id
}
```

转移规则（战略层，每 2 秒评估一次）：

```text
develop ──兵力 ≥ attackThreshold──▶ buildUp
buildUp ──部队集结完毕───────────▶ attack
attack  ──部队全灭/攻下目标──────▶ develop（重置阈值并加大）
任意   ──基地附近出现敌方单位────▶ defend（消灭后回原状态）
```

### 2. 战略层：建造顺序

「按表造」而不是「按需求计算」，是原型期最稳的策略：

```ts
const DEFAULT_BUILD_ORDER = [
  'powerPlant', 'refinery', 'barracks', 'powerPlant',
  'guardTower', 'factory', 'radar',
];
```

遭遇战开始时 AI 与玩家一样只有一辆 MCV。战略层第一次醒来会发出 `deploy` 命令，主基地落地后才开始建造；每轮思考只有在钱够、前置建筑齐全且电网能承受的情况下，才把下一项放到基地旁的合法格。要更聪明的 AI，以后把「按表」换成「按对手阵容反制」（侦察 + 兵种克制表），但**现在不要做**。

### 3. 战术层：编组与进攻

```ts
export interface Squad {
  id: number;
  unitIds: number[];
  role: 'harvest' | 'attack' | 'defense';
}
```

- 采矿车出生即编入 `harvest` 组，自动循环执行挖矿（复用 [06 的采矿逻辑](./06-economy.md)）。
- 攻击单位攒进 `attack` 组，达到阈值后：先集结到基地旁一个集结点，再对目标（优先选「最近敌方建筑」或「敌方基地」）发 attack 命令。
- **进攻要有波次感**：一波打出去，AI 回到 develop 重新攒兵，阈值每波递增（第一波 6 个兵，第二波 10 个……），玩家压力逐步上升。

### 4. 回防

`defend` 状态用「受袭事件」触发：战斗系统在「有建筑被攻击」时写一条事件，AI 战略层读到后把 `defense` 组派回受袭点。第一版简化：**基地附近 15 格内出现敌方单位** → 所有 idle 攻击单位切换攻击该敌人。

## 与其他系统的关系

- 完全建立在 [01 命令系统](./01-architecture.md)、[04 寻路](./04-selection-pathfinding.md)、[05 战斗](./05-combat.md)、[06 经济](./06-economy.md) 之上——AI 不绕过任何玩家也要走的路径，这是「AI 是命令生产者」原则的直接结果。
- 阶段八回放时，AI 的思考全部由确定性逻辑 + 种子随机产生，重演自然一致。

## 风险与注意事项

- AI 思考逻辑必须只用 `state.random()`（种子随机）和 tick 计时，**禁止 `setTimeout`**——那会让回放里 AI 行为漂移。
- 「AI 卡住」是 RTS 最恶性的 bug：寻路失败、没钱、队列满都会让 AI 静默挂机。战略层每次思考都要做「兜底」：如果 10 秒内没产生任何有效行动，强制执行一个保底动作（采矿/造最便宜的兵）。
- 进攻目标选择别做太复杂的威胁评估，先「打最近建筑」，玩起来再调。
- 回防逻辑要防「无限拉扯」：敌人一骚扰，全军来回跑。给回防设置冷却时间。
