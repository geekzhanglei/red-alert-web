# 04 · 阶段三：框选、A* 寻路与多单位落点分配

## 目标

加入拖拽框选、多单位移动、障碍物与 A* 寻路；多个单位去同一目标时自动散开落点，不叠成一团。

## 验收标准

- [x] 拖拽拉出选择框，框内所有己方实体（单位或建筑）被选中。
- [ ] 右键目标格，单位沿最短路径绕过水/岩石/建筑移动。
- [ ] 多单位同时去同一目标，各自占据目标附近不同的格，不重叠。
- [ ] 移动路径若被新障碍堵死，单位停在最近可达点（或返回 idle），不死循环、不卡死。

## 设计意图

**为什么寻路用 A\* 在网格上做，而不是其他算法？**

网格地图小（64×64）、障碍明确（一格能不能走），A\* 是「点到点最短路径」的标准解：实现直白、可加代价函数（地形代价、避开危险区）。它不追求一次算很多目标的最优（那是 flow field 的活），但对 RTS 的「点到点」命令完全够用。先上 A\*，等后期几百个单位同时寻路成为瓶颈，再把「大部队走同一方向」的群体寻路换成流场——那是优化，不是前置。

**为什么多单位要用「落点分配」而不是直接都压到目标格？**

一堆单位右键同一个点，如果都往那个点挤，寻路算出来同一格会互相堵死、视觉上叠成一团。解决方式不是让寻路更聪明，而是在**命令应用阶段**就把目标「分摊」成多个落点：以目标为中心，按同心环（spiral）找最近的空闲可走格，给每个单位一个不同落点。这样寻路照旧一对一，复杂度不涨，效果却接近编队。

**为什么框选命中判定在网格/世界空间做，不在屏幕像素做？**

选择框是屏幕上的矩形，但要选中「哪些实体」是地图世界坐标问题。标准做法：屏幕矩形四角反投影成地图世界坐标 → 得到世界空间矩形；再把实体的逻辑格坐标用 `gridToScreen` 投影为同一套地图世界坐标，判断实体地面锚点是否落在矩形内。摄像机缩放/平移后依然正确；不能直接拿格坐标与像素坐标比较。

```ts
  // 每次弹出 f 最小的节点，只扩展上/下/左/右，路径在等距画面中表现为折线
  // 回溯 parent 链得到 path（不含 start，含 goal）
}
```

要点：

- **启发式**使用曼哈顿距离：`h = |dx| + |dy|`，与四方向网格的实际步长一致。
- **移动约束**只允许上、下、左、右四个方向；目标在斜对角时，单位会先沿一条轴移动，再沿另一条轴转弯，避免直接斜穿地图。
- `canTraverse` 由调用方传入，寻路函数不关心具体地形规则——这样障碍物（`walkable`）和建筑占用（`occupiedBy`）共用一套逻辑，规则还能随时扩展（例如「步兵能过山、坦克不能」）。
- **性能护栏**：open 列表用二叉堆而不是线性扫描；加一个「最多展开节点数」上限，超限直接返回「不可达」，防止极端地图拖慢 tick。

### 2. 占用与重算

建筑/单位占据的格要写进 `tile.occupiedBy`（阶段三先用「单位静止时占一格」的简化版，阶段五建筑占地用 `footprint` 多格）。移动系统在单位「离开旧格、进入新格」时更新占用。当单位的目标格中途被占，寻路结果作废，需要重算——第一版策略：**目标格被占就停下或换落点，不追求实时绕路**。实时绕路是后期的事。

**移动中的单位不阻塞寻路**：`canMoveTo` 只把「静止单位/建筑」占用的格当障碍，移动中的单位放行。否则多个单位相向而行会互相把对方当障碍而死锁。代价是移动单位之间可能短暂重叠——RTS 中可接受，视觉上单位自然让开。

### 3. 落点分配

```ts
export function assignDestinations(map: MapState, target: GridPoint, count: number): GridPoint[] {
  const results: GridPoint[] = [];
  // 以 target 为中心，按「到中心的切比雪夫距离」从小到大螺旋展开，
  // 收集可走且未被本批占用的格，直到凑够 count 个
  for (let ring = 0; ring < 20 && results.length < count; ring++) {
    for (let dx = -ring; dx <= ring; dx++) {
      for (let dy = -ring; dy <= ring; dy++) {
        if (Math.max(Math.abs(dx), Math.abs(dy)) !== ring) continue; // 只取当前环
        const p = { x: target.x + dx, y: target.y + dy };
        if (isWalkable(map, p) && !results.some(r => r.x === p.x && r.y === p.y)) results.push(p);
      }
    }
  }
  return results;
}
```

命令应用时：给选中单位按顺序发 `move` 命令，目标分别是分配出来的落点。这样单位既散开、又不互相挡。

## 风险与注意事项

- 寻路最怕「不可达时死循环」：一定要有开放节点上限和不可达返回。
- 别把「落点分配」做进寻路函数——它是命令层的职责，混在一起会破坏一对一寻路的纯粹性。
- 框选反投影务必用「世界空间」，先把屏幕坐标减去摄像机偏移再投影（[02 的反投影约定](./02-map-coordinates.md)）。
- 现在只做「点到点」路径，不要上 flow field；群体移动先用「领队 + 跟随」或落点分配顶着。
