# 08 · 阶段七：战争迷雾与小地图

## 目标

加入按玩家区分的战争迷雾（未探索 / 已探索不可见 / 可见），以及只显示己方已知信息的小地图。

## 验收标准

- [ ] 地图初始全部黑暗；己方单位/建筑周围一定范围亮起。
- [ ] 单位走过后，地形保留为「已探索但灰暗」，敌人消失后不再显示其位置。
- [ ] 小地图只显示己方视野内/探索过的信息，不泄露敌方动向。
- [ ] 双阵营各自拥有独立视野（玩家 vs AI 视野互不干扰）。

## 设计意图

**为什么迷雾分「三态」而不是「二态」（可见/不可见）？**

二态迷雾（没视野就全黑）会让玩家对「我探索过的地形」失忆，地图感很差。经典 RTS 的三态更符合直觉：

- **未探索**：完全未知，画纯黑。
- **已探索但不可见**：地形可见但灰暗，敌人**不显示**（或显示最后已知位置，第一版不做「最后已知」，直接不显示）。
- **可见**：当前有己方单位视野，全部实时显示。

三态只是渲染层和「玩家可见性」的规则，**不影响逻辑模拟**：迷雾里敌人的采矿、造兵照常运行（这本来也是确定性逻辑的自然结果——逻辑层不知道也不该知道「玩家看不看得见」）。

**为什么可见性按玩家存、按 tick 重算？**

每个玩家（含 AI）都有独立视野，需要独立的一份可见性数据。重算方式：每个逻辑 tick，把所有己方有视野的单位/建筑周围的格子标记为可见；单位移动后，上一 tick 可见而本 tick 不可见的格子自动降级为「已探索」。视野是**tick 级规则**，不是渲染帧级，这样回放里迷雾也会一致重演。

## 实现思路

### 1. 可见性数据

```ts
export const FOG_UNEXPLORED = 0;
export const FOG_EXPLORED = 1;
export const FOG_VISIBLE = 2;

export interface VisibilityState {
  // 每个玩家一张 width*height 的 Uint8Array，值取上面三态
  perPlayer: Uint8Array[];  // perPlayer[playerId][y*width+x]
}
```

用 `Uint8Array` 而不是普通数组：内存小、比较快、序列化（存档）容易。

### 2. 每 tick 更新

```ts
export function updateVisibility(state: GameState): void {
  for (const player of state.players) {
    const vis = state.visibility.perPlayer[player.id];
    // 1. 全部「可见」降级为「已探索」
    for (let i = 0; i < vis.length; i++) if (vis[i] === FOG_VISIBLE) vis[i] = FOG_EXPLORED;
    // 2. 己方所有有视野的实体，把 visionRange 内的格子标为「可见」
    for (const id of state.entitiesOrder) {
      const e = state.entities[id];
      if (e.ownerId !== player.id) continue;
      const range = state.defs[e.typeId].visionRange;
      paintCircle(vis, map.width, map.height, Math.floor(e.x), Math.floor(e.y), range, FOG_VISIBLE);
    }
  }
}
```

- `paintCircle` 画圆半径：**用圆形（欧氏距离）而不是方形**，视野边界才自然。
- 这一步是 O(玩家数 × 实体数 × 视野面积)，视野 6~8 格时开销可接受。**优化时机**：单位密集时重复涂色浪费，可给每个玩家做「脏矩形」或全图重算 + 缓存，留到性能瓶颈出现再做。
- AI 的视野同样算、同样存——AI 的目标选择将来可以用它（「AI 只知道它看见的敌人」），现在先只用于渲染公平。

### 3. 渲染三态

渲染时对每个地块查当前玩家的可见性：

```text
未探索   → 纯黑（不画地形，只画一层黑）
已探索   → 画地形，再盖一层 50% 黑（灰暗效果）
可见     → 正常画地形
```

实体渲染同样查可见性：**只有「可见」格内的敌方实体才画**；己方实体永远画。这保证敌人不会穿墙现形。

### 4. 小地图

- 小地图是一块独立的 HTML canvas（或 Phaser 里的独立视口），每帧（或每 5 帧）重绘一次。
- 数据源是 `GameState` + 玩家可见性：地形底色按「已探索」绘制，敌方实体只画「可见」的，己方实体画亮点。
- 点击小地图跳转摄像机（阶段八的打磨项，先只显示）。

## 与其他系统的关系

- 视野数据由 [02](./02-map-coordinates.md) 的地图和所有实体的 `visionRange` 驱动，在 [01 tick 顺序](./01-architecture.md) 的「可见性」一步执行（排最后，保证本 tick 的移动/战斗结果先就位）。
- [07 AI](./07-ai.md) 未来可读取自己的可见性，实现「只对看见的敌人反应」，让 AI 更公平。
- 存档（[09](./09-save-replay.md)）要序列化可见性数组，否则读档后迷雾错乱。

## 风险与注意事项

- 迷雾只挡玩家的眼睛，**不要**把「不可见」做成逻辑规则（比如「不可见的敌人不参与战斗」）——那会破坏确定性模拟的统一性。
- 单位进入/离开视野时，小地图和主画面要同步刷新，否则出现「小地图看得到、主画面没有」的穿帮。
- 三态降级（可见→已探索）必须在重标「可见」**之前**做，顺序反了视野会残留一格。
- 第一版不做「最后已知位置」（敌人消失后在迷雾里留影子），这是锦上添花，等核心玩起来再加。
